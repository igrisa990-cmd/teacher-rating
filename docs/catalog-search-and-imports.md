# Catalog, addresses and moderated ratings

On 2026-10-12 the active directory has 5,132 schools: 1,059 license-register organizations (988 in Moscow Oblast) and 4,073 additional OpenStreetMap records with explicit locality/street/house addresses. These are different evidence classes. Neither source proves a current staff list. The 36 staff profiles imported from the official [MAOU Gymnasium 1 staff page](https://maoug1.ru/sveden/employees) are linked to OGRN 1035002455993 after comparing its [legal name and address](https://maoug1.ru/sveden/common) with the license record. No reviews, emails, phone numbers, photographs or personal biographies are imported. This is **not a complete nationwide database of schools or teachers**.

The OSM source extraction contains 37,595 school-tagged objects. The published batch excludes missing names, incomplete addresses, specialized non-general schools, unresolved boundaries and conservative duplicates. Moscow Oblast map records are excluded in favor of the separate license register. Missing-address records require further source enrichment, not invented locations. `prepare-osm-schools.cjs` prepares a reviewable batch only; it does not write production. Regional assignment uses the OSM-derived [geoBoundaries RUS ADM1](https://www.geoboundaries.org/api/current/gbOpen/RUS/ADM1/) simplified polygons (2017), so boundary-adjacent records may need correction. See the snapshot reports and ODbL notice in `data/registry`.

`search_catalog` is a security-invoker RPC with RLS, generated GIN search documents, region/city filtering, stable order and 20 results plus a lookahead row. The UI debounces input and ignores stale responses. The older home/community modules still use a paginated local catalog cache; larger nationwide imports should replace those modules' cache scans before expanding far beyond this release. Phone OTP is implemented, but the hosted SMS provider remains disabled: see `real-accounts.md`.

New school/teacher submissions use `submit_catalog_entry`. Teachers require an existing school selected by search; schools require a name and address. An explicit rating 1–5 is mandatory; a comment/source link is optional. Requests and draft ratings are visible only to their owner and moderators. Machine verification cannot publish a rated request. Authorized manual approval publishes the entity and the owner's rating atomically. `ON CONFLICT DO NOTHING` preserves an already-existing rating. Repeated decisions do not duplicate reviews, and teacher criteria remain NULL until the user actually supplies them. Rejected requests publish nothing. Moderator membership comes from `catalog_moderators`, never editable profile metadata.

Address autocomplete uses [Photon](https://github.com/komoot/photon) with an 800 ms debounce, RU filter, six suggestions, cancellation, a bounded local query cache, keyboard navigation and manual fallback. Suggestions are OSM-derived and attributed. The public demo endpoint allows reasonable use but has no availability guarantee and can throttle requests. For scale, configure `RUNTIME_CONFIG.addressSuggestUrl` with a managed or self-hosted Photon endpoint. No Yandex/Dadata key, paid subscription or contract was created. A suggestion is assistance, not proof that a school exists at that address; moderation still verifies it.

Validation: `tests/catalog-entry-sql.cjs` checks draft privacy, authorization, machine-publication blocking, atomic moderation, review ownership, idempotency, preservation of newer ratings, rejection, prefix search and archived records. `tests/staff-and-map.test.cjs` checks extraction boundaries, role filtering, contact omission, polygon holes, address completeness and deduplication. Phone tests mock delivery; they do not claim a live SMS was sent.

The Supabase advisory check found no ERROR findings. The mutable search path on `catalog_normalize` and anonymous access to moderation/queue RPCs were fixed. Existing advisory warnings remain for intentionally callable owner/moderator RPCs, public-read policies, legacy trigger-function grants, RLS query overhead and disabled password-leak checks. They are not a claim that the project has passed a complete security audit. References: [function execution exposure](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [RLS performance](https://supabase.com/docs/guides/database/postgres/row-level-security#rls-performance-recommendations), [password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
